## Public Evidence & Private Engineering Boundary

OMS IT intentionally separates public evidence from private engineering assets.

**Appropriate for public GitHub:** organization identity, verified project descriptions, official public websites, non-sensitive architecture summaries, public documentation, release/evidence records, technology overviews, and public contact information.

**Kept private:** production source code where not intentionally open-sourced, API keys, passwords, access tokens, environment secrets, databases, customer-confidential information, internal infrastructure details, private integrations, security-sensitive configuration, and restricted partner materials.

A private repository should not be interpreted as evidence that a project is inactive, complete, endorsed, or production-ready. Project status is stated only when supported by available evidence.
